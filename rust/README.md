# Rust rewrite

Rust port of the OpenDesign desktop stack: a **Tauri v2** shell plus an
**axum + SQLite** daemon, targeting behavioral parity with the TypeScript
implementation in `apps/daemon/` and `apps/web/`.

## Layout

| Path | Role |
| --- | --- |
| `crates/od-core` | Shared foundation: runtime path resolution (`paths.rs`), error types. |
| `crates/od-daemon` | The daemon: axum router, auth, SQLite storage, migrations, and route modules ported from TS. |
| `apps/od-tauri` | Tauri v2 desktop shell embedding `od-daemon`; Rust glue in `src-tauri/`, no UI source of its own. |

Workspace members are `crates/*` and `apps/*/src-tauri` (see `rust/Cargo.toml`).

## Verify

```sh
export PATH="$HOME/.cargo/bin:$PATH"
cd rust
cargo build --workspace
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

Web export + desktop shell (from `rust/apps/od-tauri`, Node on PATH):

```sh

npm run tauri:dev
npm run tauri:build # binary only; drop --no-bundle in package.json to bundle
```

### How the window gets its UI

The shell owns no frontend. The window loads the **embedded loopback daemon**,
which serves the built `apps/web` export (a Next.js `output: 'export'` static
tree) on the same origin as `/api`, exactly like `apps/desktop` points at the
TypeScript daemon.

Tauri still requires a `frontendDist`, so `tauri.conf.json` points at
`../web-placeholder` — a committed document that is never displayed. Keeping it
a placeholder rather than the export means a fresh clone can run
`cargo build --workspace` before any web build exists, and the interface is not
embedded into the binary at all.

The export the daemon serves comes from `npm run build:web`, which builds
`apps/web` and stages `out/` into `rust/apps/od-tauri/web-export/`.
`tauri.conf.json` maps that directory with `bundle.resources` (`../web-export`
-> `web`), so `tauri-build` copies it to `<resource_dir>/web` on every build —
dev included — and the packaged bundle installs it there (a Linux deb puts it
at `usr/lib/OpenDesign/web`). `build.rs` recreates the empty `web-export/`
before `tauri_build` runs, because the config's source path is canonicalized at
compile time and a fresh clone has none; an empty directory copies nothing and
`web_dist()` falls through to the checkout's `apps/web/out`, so
`cargo build --workspace` works before any web build. See `web_dist()` in
`src-tauri/src/shell.rs` for the full resolution order (in a bundle
`<resource_dir>/web` wins over the `../dist` legacy fallback and the checkout).

Consequences worth knowing:

- The capability that grants Tauri API access is **remote-only**
  (`capabilities/default.json`: `"local": false`, `remote.urls` =
  `http://127.0.0.1:*` + `http://localhost:*`). The port wildcard is what lets
  the shell keep its ephemeral-port fallback: Tauri matches `remote.urls` with
  the URLPattern standard, where `http://127.0.0.1` alone would match only the
  default port and leave a fallback port without API access.
- The app's own commands must be declared twice. `src-tauri/build.rs` lists
  them for `tauri_build::AppManifest`, which autogenerates
  `permissions/autogenerated/*.toml` (`allow-<command>`); the capability then
  grants those `allow-*` permissions by name. Tauri enforces the ACL for every
  remote origin, so a command absent from either list is refused
  (`not allowed. Command not found`), and with no app manifest at all every
  command fails with `Plugin not found`. Adding a `#[tauri::command]` means
  touching `commands.rs`, `build.rs`, and the capability.
- The web app talks to the shell through the `__od__` host bridge, not through
  `@tauri-apps/api` imports; without it the app runs in browser mode (see
  bead `open_design_rust-7c7.2`). Tauri does inject `window.__TAURI_INTERNALS__`
  into the remote page, so the bridge can be built on `invoke` without a custom
  protocol.
- `OD_UI_DEV_URL` overrides the window URL for an HMR loop against a dev web
  server; `OD_WEB_DIST_DIR` overrides the export the daemon serves.

### Verifying the shell headlessly

The shell runs under `Xvfb` with software GL, so the window can be exercised on
a machine with no display:

```sh
Xvfb :99 -screen 0 1440x900x24 &
DISPLAY=:99 WEBKIT_DISABLE_COMPOSITING_MODE=1 LIBGL_ALWAYS_SOFTWARE=1 \
  OD_WEB_DIST_DIR=/path/to/export cargo run -p od-tauri
DISPLAY=:99 import -window root /tmp/shell.png   # screenshot
```

Point `OD_WEB_DIST_DIR` at a directory holding an `index.html` that reports
facts back to a local HTTP listener (its `location.origin`, whether
`window.__TAURI_INTERNALS__` exists, the result of an `invoke`) to observe what
the window actually loaded. `apps/od-tauri/host-probe/` is that fixture: it
renders the injected `__od__` version and client, the presence of every bridge
method group, and three real `invoke` round trips, so a screenshot is enough
evidence that the bridge and the remote-origin ACL reached the page.

```sh
DISPLAY=:99 OD_WEB_DIST_DIR=$PWD/apps/od-tauri/host-probe cargo run -p od-tauri
```

To check the *packaged* path (that the export reaches `<resource_dir>/web` and
the shell serves it there, not from the checkout), build a bundle and run its
binary with the checkout's `apps/web/out` moved out of the way:

```sh
cd rust/apps/od-tauri && npm install
node_modules/.bin/tauri build --debug --bundles deb \
  --config '{"build":{"beforeBuildCommand":"true"}}'   # web-export/ already staged
cd rust && dpkg-deb -x target/debug/bundle/deb/OpenDesign_*_amd64.deb /tmp/od-deb
# with apps/web/out renamed away and OD_WEB_DIST_DIR unset, the window below
# must still render: it can only come from /tmp/od-deb/usr/lib/OpenDesign/web
```

## Parity rules

- Route modules carry doc comments referencing their TS source
  (`file:line`); response field names match TS (camelCase).
- Errors use the JSON envelope `{"error": {"code", "message"}}`.
- Parser events reach the renderer on the **`agent` SSE lane**: the frame is
  `event: agent` and the payload carries its own `type` (`text_delta`,
  `usage`, …). Naming the frame after the type makes `apps/web` skip it. Plain
  adapters stream `event: stdout` with `{ chunk }`
  (`packages/contracts` `ChatSseChunkPayload`).
- The multi-kind `json-event-stream` parser emits each runtime's frame through
  `StreamEvent::Json` rather than a shared typed variant: a frame's key set is
  per-kind (an OpenCode `usage` frame carries `costUsd` but no
  `stopReason`/`durationMs`; a Claude one carries all three), so a shared shape
  would add or drop keys. The typed variants encode the Claude/Copilot/Qoder
  shapes only. The pump resolves the kind the way TS does —
  `def.eventParser || def.id` — and routes it through
  `protocol::json_event_kind_supported`; a kind without a ported handler stays on
  the plain lane instead of losing every line to a bare raw event.
- Every route registers in `routes.rs` **before** the `/api/{*rest}`
  catch-all.
- Filesystem access goes through the containment helpers in
  `project_dir.rs`; IDs validate with `isSafeId` (`[A-Za-z0-9._-]`,
  length 1–128, not all dots).
- Known/accepted deviations (e.g. the workspace-authority lane
  `authorizeProjectRequest`) are documented in each module's header comment —
  extend those docs when skipping behavior, never silently.
